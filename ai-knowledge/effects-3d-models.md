# 3D effect models (OBJ + MTL)

Every visual effect in the game world is an **instance of a Wavefront OBJ model** from `assets/effects/`.
The models are generated by code, loaded at startup, then placed, scaled, tinted and faded each frame.

```sh
dart run tool/generate_effects.dart    # regenerates assets/effects/*.obj + effects.mtl
```

The files are standard OBJ/MTL, so you can open them in Blender, Windows 3D Viewer, MeshLab and similar tools. Hand-edited or Blender-exported files also work, as long as they keep the conventions below.

## Authoring conventions
- Units are meters, **+Y up**. Each file starts with `mtllib effects.mtl` and uses one shared material library.
- **Billboards** (`impact_flash`, `streak`, `bar_quad`) lie in the XY plane facing +Z. At runtime `MeshBuilder.billboard(cam.yaw, cam.pitch)` turns them toward the camera.
- **Ground decals** (`shockwave_ring`, `pickup_ring`) lie in the XZ plane. Rings have radius 1 and are scaled at runtime.
- `slash_arc` sits in the XZ plane around the wielder: forward is −Z, and the bright leading edge is on the −X side. Runtime code mirrors it (scale x −1) for backhand cuts and rotates it 90° about Z for overhead cuts.
- `arrow` points along +Z. `shuriken` lies flat in XZ.
- Solid models are wound counter-clockwise seen from outside (outward normals). Flat effects are two-sided.

## Materials (effects.mtl)
| Statement | Meaning |
|---|---|
| `Kd r g b` | base color (0..1) |
| `d a` (or `Tr`) | opacity: 1 is solid, below 1 is translucent (vertex alpha is honored) |
| `illum 0` or non-zero `Ke` | emissive (unlit glow) |
| `essen_flags double emissive nofog` | engine extension (other tools ignore it): two-sided, emissive, ignore distance fog |

To build an opacity gradient, split the mesh into bands with different materials. See `slash_*` and `beacon_*`.

## Runtime
- `engine/obj_mesh.dart`:
  - `ObjMesh.parseMtl` parses the material library
  - `ObjMesh.parse` handles `v`, `f` (fan triangulation, `v/vt/vn`, negative indices) and `usemtl`
  - result: per-triangle positions, color (ARGB from Kd + d) and render flags
- `game/fx.dart`:
  - `Fx.load()` loads from the asset bundle (awaited in `GameScreen._load`)
  - `Fx.loadFromDirectory()` loads straight from disk (tests)
  - getters such as `Fx.flash` return `null` until loaded, and effects are then skipped
- `MeshBuilder.mesh(m, alpha:, tint:, tintAmount:)` emits the model with the current transform:
  - `alpha` multiplies material opacity (fade-out)
  - `tint` blends RGB toward a color (red rings, gold pickup runes, flames cooling to red)
- Cost: every instance adds its triangle count to the frame. Keep particle models tiny: flame 8, smoke 20, spark/ember 4, streak 2.

## Adding an effect model
1. Write a builder function in `tool/generate_effects.dart`.
   - Use `Obj.vert`, `face`, `outTri`/`outQuad` (auto outward winding), and the `box`, `octa`, `cylinderX`, `diamond` helpers.
   - Add any new materials to `mats`.
2. Add it to the list in `main()` and run `dart run tool/generate_effects.dart`. The script fails if a material is missing.
3. Add the name to `Fx.names` and add a getter.
4. Instance it: `b.reset(); b.translate(...); b.rotateY(...); b.scale(...); b.mesh(Fx.x!, alpha: ...)`. For transient effects, add a `PKind` and handle it in `Particles.update` and `Particles.draw`.
5. `flutter test test/effects_test.dart` checks that every file parses and its materials resolve.

## Editing models by hand or in Blender
After changing any file in `assets/effects/`, run the validator:

```sh
dart run tool/validate_effects.dart        # report
dart run tool/validate_effects.dart --fix  # also strip faces with out-of-range indices
```

It checks:
- every expected model exists
- face indices are in range
- `usemtl` names exist in `effects.mtl`
- the estimated per-frame triangle cost

`flutter test test/effects_test.dart` fails if any model loads with problems.

Loading never crashes the game:
- `ObjMesh.parse` skips invalid faces and records `warnings`.
- `Fx` disables only a broken model and logs the problem (`[Fx] file: ...` in the debug console; also in `Fx.problems`).
- `GameScreen` only waits on the world; icons and effects are optional.

**Frame cost:**
- `flame`, `smoke_puff`, `petal` and `ember` adapt automatically. When a model is heavier than its reference (16 / 24 / 8 / 8 triangles), `Game._emitScale` spawns fewer, slightly larger copies, down to 30%.
- Other particle models (`spark`, `streak`, `blood_drop`, `dust_puff`) are spawned at fixed rates, so keep them small.
- One-off models (rings, beacon, slash arc, pickups) can be detailed (hundreds of triangles).

**Exporter tips (Blender → OBJ):**
- Y-up, apply transforms.
- Triangulated or quads both work.
- Keep material names that exist in `effects.mtl`. To add a material, add it to the generator's `mats` list or append it to `effects.mtl` by hand.
- Normals/UVs (`vn`/`vt`) are fine and ignored. Lighting uses face normals from the winding: counter-clockwise when seen from outside.
- Note: `dart run tool/generate_effects.dart` **overwrites** every model with the generated originals. Don't run it after hand-editing unless you want to reset.
